# 모의 배틀과 대회 공지

학생 왼쪽 아래 **모의 배틀** → 왼쪽 ‘내가 건 배틀’, 오른쪽 ‘나에게 걸려 온 배틀’, 아래 ‘우리 반 대회’. 교사는 왼쪽 아래 **대회 개최**에서 이름·참가 조건·펫 수(1~3)·상품을 입력한다. 참가 조건은 안내 문구이며 자동 심사하지 않는다. 이번 대회 범위는 개최 및 학급 공지까지다.

## 흐름

1. 같은 반의 다른 학생 번호로 신청. 양쪽 모두 펫이 있어야 하며, 같은 두 학생의 진행 중/승인 대기 신청은 중복 생성하지 않는다.
2. 받은 학생만 승인/거부 가능. 승인하면 두 학생 모두 ‘배틀하기’ 표시.
3. 한 명이 시작하면 상대에게도 팝업이 열린다(화면 활성 상태에서 최대 약 3초 후). 창을 닫아도 진행 상태가 저장되며 다시 들어올 수 있다.
4. 시작 시 보유 펫 1~3마리를 복사하고 대표 펫부터 출전. 배틀 도중 육성 상태가 바뀌어도 복사한 능력치는 유지한다. 실제 펫/포인트에는 영향 없다.
5. 두 학생이 각각 행동을 선택하면 서버가 한 턴을 판정한다. 아직 처리하지 않은 상대 선택은 브라우저에 보내지 않는다. 기술은 습득한 목록만 선택 가능.
6. 자발적 교체는 기술보다 먼저 실행되며 한 턴을 쓴다. 쓰러진 펫은 살아 있는 후보로 무료 교체 후 다음 턴 진행. 교체 시 나가는 펫의 랭크·낙조·반사·방어·충전·연속 사용 기록은 해제된다.
7. 팀 전원이 쓰러지거나 기권하면 종료. 방어만 반복하는 경우 200턴 후 무승부. 상대 미접속 시 자동으로 행동하지 않으며 대기 또는 기권 가능.

## 서버와 저장

- `/api/battle`: 같은 출처 JSON/HttpOnly 세션 확인. 공개 액션은 신청·응답·시작·행동·대회 개최만 허용.
- `lib/duels.ts`: 파티 및 턴 상태 전이. `lib/battle.ts`의 기술 계산 재사용.
- `lib/battle-backend.ts`: 서버 난수, 권한이 확인된 DB 상태만 사용. 클라이언트 체력·피해·승자·파티 입력은 사용하지 않는다.
- 새 private 테이블 3개: `petclass_battles`, `petclass_tournaments`, `petclass_battle_requests`. 학급/참가자 접근 제한, RLS 활성, 직접 접근 권한 없음.
- 낙관적 버전 검사와 DB 요청 기록으로 동시 입력·재전송을 처리한다. 학생당 진행 배틀은 하나. 학급 단위 DB 잠금은 시작 충돌/동일 두 학생의 중복 신청 방지에 사용.
- 기존 관리자 학급 백업·초기화에 배틀/대회도 포함.

## 적용과 검증

운영 적용 전에 `supabase/migrations/20261003160000_mock_battles_tournaments.sql`을 적용한 뒤 앱을 배포한다. CLI가 생성한 파일을 기존 P2 마이그레이션 뒤에 실행되도록 순서만 조정했다. 이전 마이그레이션은 수정하지 않았다.

`npm test`는 로컬 PGlite에서 실제 마이그레이션과 서버 로직을 함께 실행해 학급 격리·권한·동시 처리·중복 방지·공개 목록의 선택 정보 제외·전체 파티 패배·교체·기권·대회 공지·관리자 초기화를 검증한다. 실제 운영 데이터에는 쓰지 않는다.
